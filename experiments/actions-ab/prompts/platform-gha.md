Use **GitHub Actions**. There is no GitHub here, so run workflows locally with act, at `{DEST}/bin/act`. There is no Docker either: use act's host mode, `-P ubuntu-latest=-self-hosted`. Its documentation is in `{DEST}/gha-docs`: GitHub's own docs pages for Actions, branch rules and code owners, with the REST reference for actions, deployments and repositories (`github-docs/`, from github/docs, unrendered), act's README at v0.2.98 (`act/`), and the act user guide (`act-docs/`, last changed 2025-05-01, so older than this act). `act --help` also works. The origins here are local paths, so under act `github.repository` is an origin's path, not `acme/<name>` as on GitHub. GitHub features that act cannot run, such as environments with required reviewers, preventing self-review, teams, branch protection and the run history, count if you configure them as code in the repository or the org (a workflow, or a script that applies the settings through the GitHub API) and explain in `HANDOFF.md` how GitHub would enforce them. You need not rebuild such a feature here. Where GitHub would perform a step (a reviewer approving, refusing a self-approval, keeping the run history), `HANDOFF.md` may give the GitHub command for it (`gh` or a REST call); a test of that step is credited when its configuration is committed and explained. For the three runs, say which steps GitHub would have performed. Say in `HANDOFF.md` what you could not run here. Write whatever glue GitHub Actions doesn't provide yourself, in any language. You may install packages.
