Seikika is an open-source framework for an internal developer portal. A portal is a catalog of what your organisation runs, the standards those things are held to, and the actions an agent can take. You configure the portal in code. The same catalog is exposed over an API, an MCP server, a CLI and a UI.

## Who you are

Four groups build with Seikika. Each group has its own loop, and a command belongs to one of them.

| You | You are here to | Start |
|---|---|---|
| Platform team | Build and run a portal | [Build a portal](/operators/) |
| Standards author | Publish scorecards other portals include | [Publish a standard](/authors/) |
| Developer or agent | Read the catalog and build on it | [Use a portal](/users/) |
| Seikika maintainer | Change this repository | [Build Seikika](/maintainers/) |

[The four SDLC layers](/concepts/layers/) is how those loops meet, and which parts run today.

## Measured, not claimed

Seikika benchmarks its own developer experience. Coding agents do real work on open-source repositories, once with Seikika and once with the alternatives: hand-written glue, a checklist, an agent building from scratch, or OpenSSF Scorecard. The bar is set before each run, and the losses are published. See [DX Benchmarks](/concepts/dx-benchmarks/).
