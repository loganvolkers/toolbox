# Benchmark design for the assessment improvement loop

## Decision and scope

Test whether Seikika helps fresh coding agents repair and independently verify real standards findings across a maintainer SDLC cycle. First compare correctness at equal budget. Then compare verified fixes per unit of cost and what survives a handoff. The primary stages are baseline and triage, repair, independent verification, and regression review. Reuse and migration are longitudinal tests of the same claim.

The design follows Seikika’s DX Benchmark protocol 2. It is a registration candidate. Freeze the repos, task units, executable oracle, prompts, instrumentation, versions, power calculation and participants before the scored round. The [retrospective](assessment-improvement-2026-11-28.md) supplies task types and risks. Hold it out of the scored corpus because this session already developed answers. [DX Benchmark protocol](https://github.com/seikika/seikika/blob/main/docs/design/dx-benchmarks.md)

## Arms

| Arm | Agent environment |
| --- | --- |
| A | Seikika with the same scanner/test facts, a campaign, a rubric, assessment briefs, check output and a baseline ratchet |
| B | Native shell, repo docs and tests, Git, and an equal-length starting task packet. This is the usual unaided agent workflow without a dedicated standards tool |
| C | The strongest practical composed workflow for these tasks, with the same underlying scanners and tests, reviewdog or equivalent diagnostics, and a versioned checklist with CSV or JSON finding IDs, evidence pointers and a CI baseline diff |

Provide the same standard in human-readable form in every arm. Give each arm a short recipe and a working example of its interface. Pin and preflight all baseline tools and dependencies. Give all arms the same model, reasoning setting, general editing tools, repository access, task order distribution, CPU/memory, and repair budget. Compare A–C first for the platform claim and A–B second for adoption value. Include installation and standard-authoring effort in a separately reported cold-start phase. Warm all arms equally in the main experiment.

## Corpus and phases

1. Select at least three independently maintained open-source repositories at pinned revisions, with a documented test command and suitable source-backed standards. Start with a CLI/library, a developer-facing service and a packaging or CI-heavy repo. Each contributes comparable task units with positive and negative checks. Use historical maintainer fixes or held-out planted gaps and confirm executability before freezing. Accept multiple correct repairs. Record seeded changes and license in an adjudicator-only manifest.
2. Include nine labeled finding types across the corpus: executable behavior, documentation accuracy, CI invocation, omitted declaration, weak evidence, unrelated evidence, stale prior pass, a correctly supported fail, and a review requiring independence. Include untouched controls and test both missing and incorrect evidence. Include a tempting superficial edit for selected tasks, such as creating an unrelated file at the required path or adding a script name solely to a CI comment.
3. Phase 1 assigns triage and repair to a fresh agent. Ask it to identify real gaps, implement changes and submit an evidence file with finding IDs, status and reproducible commands. The task budget includes verification. Freeze the submitted tree and consume the same budget rules in each arm.
4. Phase 2 assigns a fresh independent agent only the standardized handoff, the assigned arm's ordinary interface and the submitted tree. It can confirm, reject or mark findings unsure and must reproduce the decisive check. Keep the original author's identity as provenance metadata with independent identities maintained by the launcher.
5. Phase 3 applies the same controlled upstream change to each arm’s workspace. Include one non-semantic move, one real behavior regression, one rubric change and unaffected controls. A fresh agent returns a new disposition and repairs what is needed. Capture invalidation precision/recall, time to first useful signal, unnecessary re-reviews and new regressions. Count an explicit justified open or unsure disposition as honest triage. Count it as unresolved for the repair metric.
6. Reserve one new repository per later round for a transfer phase. Track initial setup separately from reuse. Test product changes in a new frozen round with all arms rerun. When diagnosing an improvement, include the previous Seikika build as a concurrent additional arm.

## Oracle and outcomes

The independent adjudicator controls hidden semantic tests and a source-backed judgment key. They receive normalized, anonymized patches and evidence packets with shared finding IDs. They do not design the experiment, implement the arms, or tune Seikika between rounds. Have two blinded readers independently score evidence fidelity on a prespecified subset, record agreement, and resolve disagreements against sources. Preserve original reasoning and verdicts with any case amendments. Measure leakage and ask adjudicators to record guessed arms before unblinding.

Primary unit is the run, aggregated over its assigned findings. Primary score is verified repair recall, true repaired defects divided by real repairable defects assigned. A repair requires both oracle acceptance and reproducible supporting evidence. Guardrails are zero new critical regressions, zero rejected stale passes or self-reviews accepted as current, and a false-closure rate at most 5%. Report factual triage accuracy, per-type recall, severity and coverage, raw test outcomes, independent review precision/recall and reproducibility. Benchmark judgment uses those signals even if the arm’s own campaign disagrees.

Register the following candidate bars before scoring after a telemetry and headroom pilot:

- Effectiveness against C requires at least a 10 percentage point lift in verified repair recall, with the registered corrected inferential interval excluding zero and guardrails met. Report the same comparison to B, with multiplicity handling registered for both comparisons.
- Efficiency against C requires at least a 20% reduction in agent-visible tool-result characters across phases 1–3 at verified repair recall within 5 percentage points of C, with guardrails met and the protocol 2 exact two-sided Mann–Whitney test passing Holm-adjusted alpha 0.05 across registered cost hypotheses. Count characters after agent-side truncation, including stdout and stderr exposed to the agent. Preserve raw byte counts separately. Require adequate headroom on recall and ensure lower reads do not come from early failure.
- Record p50 and p90 wall time, uncached/cached input and output tokens, reasoning tokens when available, total cost, command/test time, human supervision minutes, tool calls by class, and time from first verified repair to published verification. These are descriptive unless a separate measured hypothesis is frozen. Exact provider token telemetry is optional and unavailable measurements stay null. No replacement metric can decide a frozen hypothesis once the run begins.

## Sampling and analysis

Preflight an excluded dry run per arm and phase to verify all instruments, full outputs for non-zero exits, executable oracle and absence of answer leaks. Run an excluded pilot of fresh agents on held-out tasks to estimate variance, failure modes and quality ceiling. Register the smallest detectable effect at 80% power on the real run allocation using simulation with pilot distributions. Vary effect size and publish the simulation seed, code and sensitivity to pilot spread. Start planning at ten runs per arm per repo, then increase for sufficient power. Observe the protocol floor of five fresh runs per arm per cost phase. If the funded design cannot detect the registered effect, mark the claim exploratory before scoring.

Randomize arms within repository and task blocks with a published seed after freezing prompts. Each launch gets its own checkout and isolated offline seeded environment. Preserve assigned runs including budget exhaustion, crashes and null telemetry. Drop and repeat only predeclared harness faults such as fixture corruption, wrong image digest or capture loss affecting required correctness evidence. Show all individual runs and the range and median per arm. Use a blocked randomization test for repair recall and a repository-block bootstrap interval for the effect. Reserve protocol 2’s exact Mann–Whitney cost test for the prespecified independent run-level comparison, and report repo- and phase-stratified sensitivity. Publish labels holds, fails, inconclusive or void with the preregistered conditions and all losses.

## Replay contract

Freeze a round manifest with repo/tree/context hashes, model and harness versions, tool images and cache hashes, budget, prompts, fixture and oracle digests, arm definitions, stopping rules, planned sample size and randomization. Persist per-run events as append-only JSONL and a normalized run table. Each run retains the initial tree digest, launch parameters, actual tool calls and results, exit codes, timestamps, final binary Git diff, arm-produced evidence, verification outputs, independent oracle outcomes, review dispositions and exclusion reason. Store raw signed provider usage separately when supported. Redact sensitive values before publication and retain a checksum manifest.

A launcher should create assigned workspaces from the manifest, run one agent per workspace, capture stdout/stderr and tool-result truncation, enforce the common budget, and export artifacts before workspace cleanup. A scorer should consume only anonymized artifacts and return per-finding oracle outcomes. An analyzer should verify hashes, compare against expected run IDs, flag missingness by arm, apply the frozen bars and emit a machine-readable plus human-readable results table. Record launcher, scorer and analyzer versions.

The [example event contract](evidence/assessment-improvement-2026-11-28/benchmark-events.jsonl) gives sample events. Implementation starts with the excluded dry run, then a fixed registration and run package under `experiments/assessment-improvement-ab/` and its catalog entry under `.seikika/benchmarks/` once pilot evidence and pinned commits are available. Use separate roles for benchmark designer, launcher and adjudicator. Re-run the frozen corpus for releases and refresh the holdout on a fixed cadence. Pin a second unchanged baseline across releases to expose agent, runtime or dependency drift.
