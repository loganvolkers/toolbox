# Seikika README gap analysis

Extend the [documentation style guide](../../site/src/content/docs/maintainers/writing.md#write-a-readme) with README-specific guidance. The [public documentation audit](public-docs-2026-11-26.md) established how Seikika writes for a reader, describes availability, and verifies examples. A README uses the same rules and has a different job. It helps readers arriving through a repository or registry choose a next step.

## How the peer review worked

Read seven primary README sources. Backstage is the closest product peer. uv, Deno, and ripgrep are Rust developer tools with distinct onboarding approaches. Axum and Ruff represent a public Rust library and an internal crate published in a Rust workspace. OpenFGA is the authorization service Seikika uses and provides a useful server evaluation path. Source links point to the files reviewed. The Git blob IDs identify the content observed on November 26, 2026.

For each README, start at the title and ask four questions. Can the reader identify the tool and intended use? Can they find a concrete first result or an appropriate handoff? Can they tell which versions or environments apply? Can they find a reference, help, or a next step? A result can be delegated when the destination is named and the README tells the reader what they will find there. This is an editorial comparison of published files, with peer examples reviewed in source.

| README | Purpose and first result | Scope and next step | Use in Seikika |
| --- | --- | --- | --- |
| Backstage | Lists the developer portal features before directing readers to Getting Started. The README delegates setup to the docs. | Separate sections cover project roadmap, docs, contribution, chat, and security. The long branding and community blocks compete with the first task. | Route readers to the two existing tutorials and keep contribution and help visible. [README](https://github.com/backstage/backstage/blob/master/README.md), blob `431dfc5`. |
| uv | Gives installation choices, then separates projects, scripts, and tools. The `uvx pycowsay` example includes visible output. | Labels platform-specific commands and points to detailed installation and command help. Maintaining several install snippets adds upkeep. | Name the task and its visible outcome. Keep platform and release instructions in the install guide. [README](https://github.com/astral-sh/uv/blob/main/README.md), blob `66caaf9`. |
| Deno | Pairs install choices with a first program and then a local HTTP server. Readers see what to run and where to look. | Separates building from source and points contributors to a dedicated guide. The examples fit a single runtime. | Give the CLI an immediate version check and hand off to a full tutorial for the two-binary workflow. [README](https://github.com/denoland/deno/blob/main/README.md), blob `8173eb9`. |
| ripgrep | Defines the recursive search behavior in the opener, including what it skips. Side-by-side search commands make comparisons concrete. | Quick links lead to the guide, FAQ, and changelog. Extensive benchmarks add depth and push task navigation farther down the page. | Put a consequential default or limit next to the capability. Keep benchmark findings linked from the root. [README](https://github.com/BurntSushi/ripgrep/blob/master/README.md), blob `a76da52`. |
| Axum | Defines the crate in one sentence and shows a working route. | Marks breaking changes and the minimum Rust version, then links to examples, API docs, and help. An example is a good fit for a library intended for direct use. | Point to the supported integration or source entry point. Add a direct example when the crate has an audience for that API. [README](https://github.com/tokio-rs/axum/blob/main/axum/README.md), blob `fec56a4`. |
| Ruff linter | Identifies the published crate as an internal Ruff component and points to the parent tool. | Names the matching Ruff version and links to pinned source and the versioning policy. This keeps the page short, though it gives maintainers little context about the component's job. | Give internal crates a clear responsibility and link to source at the audited revision. [README](https://github.com/astral-sh/ruff/blob/main/crates/ruff_linter/README.md), blob `7bf0718`. |
| OpenFGA | Offers a Docker quickstart, a local playground, and installation verification. | Labels the local evaluation scope and links to production setup. The quickstart and install sections repeat some commands. | Distinguish local evaluation from shared deployment and maintain each procedure in one place. [README](https://github.com/openfga/openfga/blob/main/README.md), blob `ec713e6`. |

Using the guide as written would preserve the voice but leave crate scope, registry links, and repository entry points implicit. A separate guide would duplicate the standards for voice, accessibility, and verifying examples. Extending the existing guide covers those README decisions in one place.

## Inventory and gaps

The baseline is [`25a208a`](https://github.com/seikika/seikika/tree/25a208a3bc1a97f184588c512afcb12d636ce7be), after the public docs refresh and the mise reconciliation. The inventory uses tracked README paths, Cargo workspace members, pnpm members and CI subprojects, first-party package manifests, the reusable action, the operator plugin, and example and experiment entry points. Review focused on the intended reader, first visible result, version accuracy, and whether links work from the place the README appears.

| Surface | Baseline gap or finding | Change |
| --- | --- | --- |
| Root | The opener offers two tutorials, then an internal milestone and design index before install and contributor paths. License and help are missing as direct destinations. | Keep the two outcome-based starts, add install and help, and move design navigation to [docs/README.md](../README.md). |
| Rust workspace | 1 of 17 crates has a README. The existing telemetry README reaches outside its crate using checkout links. Libraries, the CLI, and six connector binaries need different first steps. | All 17 crates now have package READMEs and a [workspace index](../../crates/README.md). Confirm archive inclusion for every crate. Link to audited source for internal APIs. |
| npm workspace | The published UI and report packages and the docs site have entry points. The hosted UI workspace member has no README. | Add the [hosted UI README](../../ui/README.md) with its relationship to the shared components and static report. |
| Standards, action, and plugin | All nine standards packages have individual READMEs but lack a package index. pnpm-expo refers to `v0.2.0` as available and Storybook shows `0.1.2`. Neither tag existed in the observed release inventory. The action already offers a source-pin path and the plugin labels its pre-release status. | Add a [package index](../../packages/README.md). Give both affected packages a source pin that contains the package and workspace connector features. |
| Examples and experiments | The maintained examples have entry points with scope and workflow. The full-recompute experiment is linked from the experiments index but its directory lacks context. | Add a [full-recompute README](../../experiments/full-recompute/README.md) linking the original procedure and findings. |
| CI tooling | The GitHub integration fixture and isolated Playwright npm package lack entry points. | Add READMEs for [GitHub Emulate](../../scripts/github-emulate/README.md) and [Playwright](../../scripts/playwright-ci/README.md), with the owning workflow and validation scope. |
| Historical evidence and fixtures | Benchmark rounds, generated test inputs, seed repos, and nested cost-test crates belong to their parent experiment or fixture. | Use the parent entry points to locate them. |

GitHub's release inventory showed `v0.1.1` as the latest release, with `toolbox-*` binaries. The root README delegates version and build selection to the installation guide. A probe of `docs.rs/seikika-api/0.2.0` returned HTTP 404, so the crate READMEs link to source where there is no verified hosted API reference. [Release inventory](https://github.com/seikika/seikika/releases).
