# D37. Derived state: full recompute from a consistent Postgres snapshot

**Derived state: full recompute from a consistent Postgres snapshot** (critique C1). The snapshot id is the consistency token; the logical-decoding change log and object-storage checkpoints are deferred. Recompute is triggered by changes, so "no batch or nightly recomputation" (D21) still holds. DBSP comes back, behind the same derived-state contract, only if a real portal's full recompute exceeds 30 s or freshness misses 60 s p95

**Status:** ✅ supersedes D21's engine choice
