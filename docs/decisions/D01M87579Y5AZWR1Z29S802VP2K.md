# The add-action skill ends at telling people how to use the action

**Amends D01M86J769VGE6K5FJJQ76EP4AA, point 18.** That point says the `add-action` skill "covers
the whole path, from layout to handoff". The skill's last step is now *Tell people how to use it*:
how to request, approve and check a run of the action that was added. It does not prescribe a
handoff document. A handoff is the reader's task, not a step of adding an action, and naming it
fitted the skill to the actions DX benchmark, whose task ends in one
([FIT-AUDIT.md](../../experiments/actions-ab/results/FIT-AUDIT.md),
[FIT-AUDIT-r8.md](../../experiments/actions-ab/results/FIT-AUDIT-r8.md) §6).

The rest of point 18 stands: an action several repositories offer is one standard file, the same
in each, and the skill covers its layout, tests, rollout and first runs.

The shipped example and tests use `group:security` for their group approver, not a group a
benchmark task names, for the same reason.
