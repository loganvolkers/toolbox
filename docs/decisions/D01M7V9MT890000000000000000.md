# D49. Action runs: preview → confirm → dispatch → verify

**Action runs: preview → confirm → dispatch → verify.** A run succeeds only when declared CEL postconditions hold at a snapshot taken after a scoped connector refresh ("done means observed"). Confirmation is bound to the preview by a token. Executors implement `preview`, `run` with progress, `cancel` and optional `verify`. In-image and HTTP executors are the high-fidelity default; GitHub Actions is supported at a coarser preview tier; fire-and-forget webhooks or queues never count as completion and end `unverified` without a postcondition
