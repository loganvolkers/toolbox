# D95. Split portal sources by topic; diagnostics name the file a value came from; regenerate, don't merge, ratchet results

**Split portal sources by topic; diagnostics name the file a value came from; regenerate, don't merge, ratchet results.** `toolbox validate` (and every command that loads a portal) reports a problem in an `include`d file or package fragment at that file and its own JSON pointer, not the merged document's. T4T's `portal/toolbox.yaml` keeps the portal, policies, connectors, MCP text and the include list; each topic's kinds, scorecards and rubrics live together in `portal/standards/<topic>.yaml`. The connectors stay in the root: one connector's sources can't be split across files, because arrays concatenate. `portal/results.json` stays one file: its keys are sorted, so splitting it by scorecard wouldn't remove conflicts, which come from one entity changing on both sides. On a conflict in it, take the upstream copy and rerun `--update`, as with a lockfile
