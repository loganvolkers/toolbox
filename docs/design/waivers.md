# Waivers: An Accepted Failure Cites a Decision

*Status: built for repo portals, 2026-11-21 (D01M7Y5VWNAWB8K1DNMY31KQPQ0). A waiver is manifest
data. It does not hide a finding from the report. Related:
[github-actions-standards.md](./github-actions-standards.md),
[ratchets.md](./ratchets.md),
[repo-value.md](./repo-value.md).*

## 1. Conclusion

**A failure that we accept stays visible, and it names the decision that accepted it.**

| Field | What it is |
|---|---|
| `entity` | The entity id, for example `workflow:.github/workflows/release.yml` |
| `scorecard` | A scorecard in the manifest |
| `rule` | A rule on that scorecard |
| `decision` | A file `docs/decisions/<id>.md`, checked from the portal root |
| `reason` | Why this entity's rule is accepted |

The outcome is `waived`. Evidence is still recorded, so the finding is on the report. The level treats `waived` as a pass. The baseline lists the waived rule names. Deleting the waiver while the rule still fails is a regression.

Closing the gap is a new decision, then deleting the waiver. The validator does not invent that decision. It only refuses a waiver whose decision file, scorecard or rule is missing.

## 2. What this repository waives

`release.yml` is generated by dist (D98). Its zizmor findings are the template's, and the file is not edited by hand. `no-high-findings`, `no-medium-findings` and `zizmor-clean` on that one workflow are waived. The ignore file `.github/zizmor.yml` is gone, so the findings are produced and then waived. `ci.yml` and `codeql.yml` have no waiver.

## 3. What a waiver is not

A waiver is not a zizmor ignore, and it is not a way to make `--update` accept a new failure without a decision. The decision file has to exist before the waiver validates.
